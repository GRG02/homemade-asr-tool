================================================================================
สรุปบันทึกการทำงานและสถาปัตยกรรมระบบ: Thai Speech-to-Text (Pathumma STT)
================================================================================

1. ภาพรวมสถาปัตยกรรมของระบบ (System Architecture Overview)
--------------------------------------------------------------------------------
- โมเดลหลัก: `nectec/Pathumma-stt-th-fastconformer-rnnt-large` (โดย NECTEC)
  - สถาปัตยกรรม: FastConformer-RNNT (Recurrent Neural Network Transducer) ขนาด ~441 MB
  - การประมวลผล: ทำงานบน GPU (NVIDIA GeForce RTX 3060) ด้วย Data Type `torch.bfloat16`
- การรับสัญญาณเสียง: ไมโครโฟนผ่าน `sounddevice` (Sampling Rate 16,000 Hz, Mono, Float32)
- การควบคุม: กดค้างเพื่อพูด (Push-to-Talk) ด้วยปุ่ม `Win + Z`
- การส่งออกข้อความ: จำลองการวางข้อความอัตโนมัติ (`Ctrl + V`) ลงตำแหน่งเคอร์เซอร์ผ่าน `pyperclip` & `keyboard`
- การประมวลผลคำ: ระบบ Inverse Text Normalization (ITN) 2-Pass แปลงตัวเลขและเครื่องหมายคณิตศาสตร์


2. ระบบควบคุม Push-to-Talk (Win + Z) และ Clipboard Auto-Paste
--------------------------------------------------------------------------------
- กลไกการทำงาน:
  - ใช้ `keyboard.hook(on_key_event)` ดักจับสถานะคีย์บอร์ดระดับล่าง เพื่อตรวจจับการกดปุ่ม Windows 
    (`win`, `left windows`, `right windows`) ควบคู่กับปุ่ม `z`
  - กดค้างทั้งสองปุ่มพร้อมกัน = เริ่มบันทึกเสียง (`[*] Listening...`)
  - ปล่อยมือออกจากปุ่มใดปุ่มหนึ่ง = สิ้นสุดการบันทึกและเริ่มประมวลผล (`[*] Processing...`)
- การป้องกันคีย์บอร์ดค้าง (Non-blocking Threading):
  - แยกกระบวนการถอดเสียง (`asr_model.transcribe`) และการกดวาง (`Ctrl + V`) ไปทำงานบน Background Thread 
    (`threading.Thread(daemon=True)`) เพื่อไม่ให้บล็อก Keyboard Event Loop ของระบบ
- การจัดการคลิปบอร์ด:
  - สำรองข้อความเดิมในคลิปบอร์ด (`old_clip = pyperclip.paste()`)
  - คัดลอกข้อความที่ถอดเสียงได้แล้วสั่งจำลองกด `Ctrl + V`
  - คืนค่าคลิปบอร์ดเดิมกลับคืน เพื่อไม่ให้ข้อความของผู้ใช้ที่ก๊อปปี้ไว้ก่อนหน้าสูญหาย


3. ระบบชะลอความเร็วเสียง 0.90x โดยไม่เพี้ยนระดับเสียง (WSOLA Time-Stretching)
--------------------------------------------------------------------------------
- วัตถุประสงค์: ชะลอความเร็วเสียงพูดลงเหลือ 0.90x ก่อนส่งเข้าโมเดล เพื่อช่วยให้ AI จับคำพูดเร็วได้แม่นยำขึ้น
- อัลกอริทึม: WSOLA (Waveform Similarity Overlap-Add) พัฒนาด้วย NumPy 100% 
  (ไม่ต้องติดตั้งแพ็กเกจเสริมภายนอกขนาดใหญ่ เช่น librosa)
- รายละเอียดทางเทคนิค:
  - ตัดสัญญาณเสียงเป็นเฟรมย่อย 25ms (400 samples ที่ 16kHz) ด้วย Hann Window
  - ขยายระยะเวลาออกด้วยอัตราส่วน 1 / 0.90 (~1.11x)
  - ใช้ Cross-correlation ค้นหาตำแหน่งเฟสของคลื่นเสียงที่กลมกลืนกันที่สุดในการ Overlap-Add
  - รักษาระดับ Pitch (ความถี่เสียง) และ Formant เดิมไว้ 100% ป้องกันเสียงก้องหรือเสียงเพี้ยน
  - ความเร็วในการประมวลผลสูงมาก (~9 มิลลิวินาที สำหรับคลิปเสียง 5 วินาที)


4. ระบบตัวจับเวลาสรุปสถิติตัวอักษรทุกๆ 1 นาที (1-Minute Statistics Summary)
--------------------------------------------------------------------------------
- วัตถุประสงค์: รวบรวมทุกประโยคที่พูดในรอบ 1 นาที คำนวณความยาวตัวอักษรทั้งหมด นำมาหารสาม (`ความยาว / 3`) 
  และแสดงผลรายงานสถิติใน Terminal
- การออกแบบ:
  - ใช้บัฟเฟอร์ `minute_sentences = []` ควบคุมความปลอดภัยด้วย `threading.Lock()` (Thread-safe)
  - ทำงานผ่าน Background Worker Thread (`minute_timer_worker`) วนรอบทุกๆ 60 วินาที
  - ในแต่ละรอบ 1 นาที จะคำนวณ:
    1) จำนวนประโยคที่พูดในรอบนั้น
    2) จำนวนตัวอักษรรวม (`len(combined_text)`)
    3) ผลลัพธ์ตัวอักษรหารสาม (`char_count / 3`)
    4) ตัวอย่างข้อความรวมในรอบ 1 นาที


5. การแสดงผล Terminal ภาษาอังกฤษและระบบปิด Warning (Clean Output)
--------------------------------------------------------------------------------
- ข้อความสถานะทั้งหมดแสดงผลเป็นภาษาอังกฤษ:
  - `Loading {MODEL_NAME} on {DEVICE} ({TORCH_DTYPE})...`
  - `Ready! Hold 'Win + Z' to speak, release to paste text (1-min stats summary active | Press Ctrl+C to exit)`
  - `[*] Listening...`
  - `[*] Processing...`
  - `>> Output: {text}`
  - `[⏱️ 1-Minute Statistics Summary]`
- การปิด Warnings เพื่อความสะอาดตา:
  - ซ่อนข้อความ OneLogger telemetry ตอนเปิดโปรแกรม
  - ปิด NeMo Lhotse Dataloader Warnings (`dataloader:881`, `dataloader:533`) ระหว่างถอดเสียง


6. การตั้งค่าโมเดล Pathumma STT และการแก้ปัญหา NeMo บน Python 3.11
--------------------------------------------------------------------------------
- ปัญหา: NeMo 3.0.0 บน Python 3.11.0 เกิดข้อผิดพลาด 
  `TypeError: TarFile.extract() got an unexpected keyword argument 'filter'`
  (เนื่องจากพารามิเตอร์ `filter="data"` มีเฉพาะใน Python 3.12+)
- วิธีการแก้: แก้ไขไฟล์ `.venv/Lib/site-packages/nemo/utils/tar_utils.py` ให้ครอบ `try-except TypeError` 
  หากไม่รองรับ `filter` ให้เรียก `tar.extract(member, extract_to)` ตามปกติ ทำให้อ่านไฟล์ `.nemo` สำเร็จ 100%
- การดาวน์โหลดและแคชโมเดล:
  - ใช้ `huggingface_hub.hf_hub_download` ดึงและแคชไฟล์ `pathumma-stt-th-fastconformer-rnnt-large.nemo` (~441 MB)
  - โหลดเข้าสู่หน่วยความจำด้วย `EncDecRNNTBPEModel.restore_from()`


7. การทดสอบความเร็วเครือข่าย Mirror และระบบ Local Cache / Fallback
--------------------------------------------------------------------------------
- ผลการทดสอบความเร็วการเชื่อมต่อจากเครือข่ายในประเทศไทย:
  1. PyPI Official (Fastly/Cloudflare CDN): ~54.6 ms (เร็วที่สุด)
  2. Hugging Face Official Hub: ~77.8 ms (ความเร็วดีเยี่ยม)
  3. HF-Mirror (https://hf-mirror.com): ~432.5 ms (เสถียร ใช้เป็น Mirror สำรอง)
  4. Aliyun Mirror: ~1,022 ms
  5. Tsinghua / USTC: เกิด Timeout หรือ 403 Forbidden
- ลำดับการโหลดโมเดลใน `patthumma.py`:
  - ลำดับที่ 1 (Local Cache): เช็คโหลดจากแคชในเครื่องทันที (`local_files_only=True`) เปิดโปรแกรมได้ทันทีแบบ Instant Boot
  - ลำดับที่ 2 (Official Hub): หากไม่มีไฟล์ จะดาวน์โหลดตรงจาก Hugging Face
  - ลำดับที่ 3 (Auto Fallback): หากการเชื่อมต่อขัดข้อง จะสลับไปใช้ `https://hf-mirror.com` อัตโนมัติ


8. การแก้ไขปัญหา DLL Conflict (cublasLtGetEnvironmentMode)
--------------------------------------------------------------------------------
- ปัญหา: เมื่อเปิดโปรแกรม เกิดหน้าต่างแจ้งเตือนจาก Windows:
  `The procedure entry point cublasLtGetEnvironmentMode could not be located in dynamic link library ... cublas64_12.dll`
- สาเหตุ: เกิดการชนกันของเวอร์ชัน DLL ระหว่าง PyTorch (CUDA 12.4) ที่มี `cublasLt64_12.dll` ในตัว 
  กับแพ็กเกจ `nvidia-cublas-cu12` (CUDA 12.9) ที่ถูกโหลดซ้ำซ้อนผ่าน `ctypes.CDLL`
- การแก้ไข: ลบโค้ดบล็อกการโหลด DLL แบบแมนนวลออกทั้งหมด และถอนการติดตั้ง `nvidia-cublas-cu12` 
  เนื่องจาก PyTorch มีชุด CUDA 12.4 Runtime ของตัวเองในตัวอย่างสมบูรณ์แบบอยู่แล้ว


9. ระบบ Inverse Text Normalization (2-Pass Thai Number & Math Normalizer)
--------------------------------------------------------------------------------
- การทำงานแบบ 2 ขั้นตอน (Two-Pass Normalization):

  [Pass 1: Thai Number Normalization]
  - แปลงตัวเลขไทยที่มีหลักสิบขึ้นไป (สิบ, ร้อย, พัน, หมื่น, แสน, ล้าน):
    - เช่น `สิบ` -> 10, `ยี่สิบเอ็ด` -> 21, `หนึ่งร้อยสามสิบสอง` -> 132, `ห้าพันแปดร้อย` -> 5800
  - การแยกตัวเลขที่พูดต่อกัน (ป้องกันการรวมผลลัพธ์เป็นก้อนเดียว):
    - เช่น `สิบ ยี่สิบ สามสิบ` -> `10 20 30` (ไม่นำมาบวกกันเป็น 60 โดยแบ่งตามการลดหลั่นของหลักตัวเลข)
  - แปลงตัวเลขโดด 0-9 ที่พูดเรียงกันตั้งแต่ 2 ตัวขึ้นไป:
    - เช่น `ศูนย์ แปด หนึ่ง สอง` -> 0812, `เก้า เก้า` -> 99, `สอง ห้า หก เจ็ด` -> 2567
  - การข้ามคำที่พูดถึงแค่หลักเฉยๆ (Bare Multipliers):
    - หากพูดถึงแค่หลักเฉยๆ โดยไม่มีตัวเลขประกบข้างใดข้างหนึ่ง (เช่น "หลักร้อย", "หลักสิบ", "มีเป็นร้อย", "เป็นล้าน") จะไม่แปลงเป็นตัวเลข
  - ข้อยกเว้น: เลขโดดตัวเดียวเดี่ยวๆ เช่น `หนึ่ง`, `สอง`, `สาม` จะคงเป็นคำภาษาไทยเดิมไว้ (เช่น "มีคนหนึ่งคน", "รออีกสองวัน")

  [Pass 2: Math Operators & Decimal Normalization]
  - ตรวจจับคำเครื่องหมาย: `จุด` (.), `บวก` (+), `ลบ` (-), `ขีด` (-), `คูณ` (*), `หาร` (/), `ยกกำลัง` (^)
  - เงื่อนไข: ต้องมีตัวเลขขนาบข้างทั้งฝั่งซ้ายและฝั่งขวาเท่านั้น
  - โอเปอเรเตอร์ "ขีด" (-) และ "จุด" (.):
    - แปลงโดยไม่เว้นวรรค เช่น `113ขีด002` -> `113-002`, `113 ขีด 002` -> `113-002`, `สาม จุด ห้า` -> `3.5`
  - กฎพิเศษ: อนุญาตให้แปลงเลขโดดที่อยู่ติดกับเครื่องหมายเป็นเลขอารบิกทันที เช่น:
    - `ห้า บวก สาม` -> 5 + 3
    - `หนึ่งร้อย ลบ สิบ` -> 100 - 10
    - `สิบ ขีด ยี่สิบ` -> 10-20
    - `หนึ่ง ขีด สอง` -> 1-2
    - `สอง ยกกำลัง แปด` -> 2 ^ 8
    - `สิบ หาร สอง` -> 10 / 2
    - `ห้า คูณ หก` -> 5 * 6
  - หากฝั่งใดฝั่งหนึ่งไม่ใช่ตัวเลข จะคงคำภาษาไทยเดิมไว้ เช่น "จุดเริ่มต้น", "คะแนนบวก", "ขีดเส้นใต้", "ขีดจำกัด"


10. การแก้ปัญหาและแนวทางปฏิบัติที่สำคัญ (Troubleshooting Summary)
--------------------------------------------------------------------------------
[1] Windows Terminal Encoding:
    - หน้าต่าง CMD บน Windows เริ่มต้นด้วย CP1252 ซึ่งไม่รองรับภาษาไทย
    - แก้ไขด้วยการใส่ `chcp 65001 >nul` ในไฟล์ `.bat` ทั้งหมดเพื่อบังคับใช้ UTF-8

[2] Working Directory เมื่อ Double-Click:
    - การดับเบิลคลิกไฟล์ `.bat` จากภายนอกอาจทำให้ Working Directory ชี้ไปที่อื่น
    - แก้ไขด้วยการใส่ `cd /d "%~dp0"` ที่ส่วนหัวของไฟล์ `.bat` เสมอ

[3] การควบคุม Background Execution:
    - ฟังก์ชันที่มีการประมวลผลหน่วงเวลา (เช่น การบันทึกเสียง, การถอดเสียง, การ Paste) 
      ต้องแยกไปรันบน Background Thread เสมอ เพื่อไม่ให้กระทบต่อ Keyboard Hook หรือ UI ของระบบ


11. การตั้งค่า Beam Search และ Decoding Strategy (Pathumma RNN-T)
--------------------------------------------------------------------------------
- โมเดล Pathumma FastConformer RNN-T (EncDecRNNTBPEModel) ของ NeMo มีการค้นหาคำทำนาย (Decoding) ดังนี้:
  [1] Greedy Search (ค่าเริ่มต้นเดิม: strategy='greedy_batch'):
      - ทำงานโดยเลือก Token ที่มีความน่าจะเป็นสูงสุดทีละตัว (เทียบเท่า Beam Size = 1)
      - Latency: ~79 ms บน RTX 3060 (เร็วที่สุด ตอบสนองแบบ Real-time ทันทีที่ปล่อยปุ่ม)
  [2] Beam Search (strategy='beam', ปรับผ่าน BEAM_SIZE = 3 หรือ 5 ใน run.py):
      - NeMo API: `asr_model.change_decoding_strategy(dec_cfg)`
      - สำรวจเส้นทางคำทำนาย (Hypotheses) พร้อมกัน 3-5 เส้นทาง ช่วยลดข้อผิดพลาดในคำที่ออกเสียงใกล้เคียงกัน
      - ผลการทดสอบ Latency บน RTX 3060 (คลิปเสียง 2 วินาที):
        * Beam Size = 1 (Greedy) : ~79 ms  (เร็วสุดขีด)
        * Beam Size = 3          : ~273 ms (จุดสมดุลที่แนะนำ: แม่นยำขึ้นมาก และ latency ยังต่ำกว่า 0.3 วินาที)
        * Beam Size = 5          : ~400 ms (ค้นหาลึกสุด แลกกับ latency สูงขึ้น ~5 เท่า)
- มีการใช้ `contextlib.redirect_stderr` เพื่อซ่อน Progress Bar ของ tqdm ไม่ให้กวนหน้าต่างคอนโซล
